# The agent city guide

## TL;DR

The documentation of MdExplorer's agent city: how it works, who answers for what, how to run the first round, how to
write a workflow and how to set up the workflows of an ISO 9001 quality system. Read it in order the first time, then
come back to the chapter you need.

- Start from [How the city works](01-how-the-city-works.md): the words you need to understand everything else.
- [The first round](03-the-first-round.md) uses the example workflow the city brought into the project: try it now.
- The MarkAgent knows this guide: ask it to explain a chapter with your project's own documents.

## What this guide is

When you chose the agent city «with the documentation», MdExplorer copied these documents here. They belong to the
group: you can add your own notes, but remember that a new version of MdExplorer may bring a newer one.

The city is where agents and people work together: agents prepare, people approve and decide, and every hand-over stays
written in git. This guide explains how.

## Reading order

1. [How the city works](01-how-the-city-works.md): agents, people, mail, trust, rounds and the round log.
2. [Roles and responsibilities](02-roles-and-responsibilities.md): the document that says who answers for which role
   and which agents.
3. [The first round](03-the-first-round.md): step by step with the «Hello world» workflow you find in
   `agent-city/hello.md`.
4. [Writing a workflow](04-writing-a-workflow.md): how to design work that changes hands, and how to write it with the
   MarkAgent.
5. [Setting up ISO 9001 with workflows](iso-9001/README.md): a quality system seen as a set of well-made workflows.

## Using it with the MarkAgent

The MarkAgent reads the project's documents, and so this guide too. Some questions that work well:

- «Explain chapter 1 of the city guide in simple words.»
- «I took the city owner role: what do I do now for the first round?»
- «I want a workflow for contract reviews: help me describe it following chapter 4.»
- «My agent does not start: let's look together at what is missing.»

The MarkAgent proposes the changes and asks before touching the files: you always decide.

## Where things are in the interface

| What | Where |
